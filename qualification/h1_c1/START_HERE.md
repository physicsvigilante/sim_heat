# H1-C1: a fresh authoring attempt, not another architecture review

Read only `AUTHOR_CONTRACT.md` and this instruction for the assessed attempt.
Do not inspect the repository implementation, previous solved cases, tests or
reference solutions. This task is one bounded H1 transfer experiment, not the
charter's complete two-arrangement Track A plus Track B diagnostic.

Use an LLM other than the implementation author. Disclose prior project exposure,
including previous review/design roles. A different conversation alone does not
make an implementation author independent. If the selector and author are the
same agent, disclose that too; do not claim independent task selection or blind
interpretation. No tool-generated identity should be treated as authenticated.

1. Select ONE modest transient physical teaching scenario with at least two bodies
   and materially different connections from the already developed examples.
   Do not use the previously discussed three-body branching proposal. Do not
   choose a case merely by renaming objects or changing numbers. In `TASK.md`,
   state all physical facts, topology, assumptions, chosen illustrative values,
   requested observations, and what teaching question makes it useful. Explain
   the intended structural difference without consulting implementation source.
   Save/capture this task BEFORE writing the model. Do not silently change it
   after a refusal. If unable to save a separate task artifact, return TASK.md
   first and stop for its capture rather than claim a pre-fixed task.
2. Using that fixed task and the public contract, produce `model.mo` and
   `study.json`. Do not solve intermediate temperatures, flows or time constants
   to make the model run. Standard-library byte hashing is allowed; disclose it.
   Without hashing tools, return the exact model and descriptor fields with the
   hash explicitly unresolved; the evaluator records mechanical completion as
   assistance, not an unassisted complete submission.
3. Return the ORIGINAL files and `AUTHOR_NOTES.md`: author/model identity as known,
   prior exposure, tools used, assistance, uncertainties, task-capture identity,
   and a chronological record of any corrections. Preserve the first files before
   asking for feedback. Do not run the project validator or repair its output
   before the evaluator has captured the first submission.
4. In the notes, propose one different observation set for the SAME model and one
   hypothetical change to a single rod's conductivity. Describe what a teacher
   would compare. These are unexecuted proposals, not additional native cases or
   claims of structural-editing support.

Stop after submission. Do not modify the engine, install dependencies, run
OpenModelica, launch CI, push, merge or widen the supported physics. No numeric
answer key is needed from the author. The evaluator will independently check the
physical interpretation, construct the verification data, and bind the numerical
experiment before any authorized native run.

Success is not mandatory. A refused or incomplete first attempt remains useful
recorded evidence; an easier replacement or engine repair is not first-attempt
success. Classroom effectiveness cannot be inferred from this exercise.
