# H1-N3-P0 — versioned reference migration boundary (offline design only)

**Status:** R2 DESIGN CANDIDATE. No new checking reference, runner dispatch, executable plan, host manifest, native result, external pre-output seal or independent numerical certificate is created by this milestone. It is stacked on still-draft PR63 source commit `6baba681ae1680e2fcae1ea8efbf0953afcb031b`. PR63, PR62, PR60 and PR59 remain draft and unmerged; production main and historic C1 remain unchanged.

## Why this checkpoint matters

The PR62 source-only interval generator provides a new mathematically self-checked **fixed original T1-T** 2,401/4,801-point reference candidate, including 77 exports, eight original public observations, five integrated flows and strict 100× error checks. Its output is **not** `sim_heat.reference_bundle/2` and remains labelled `independentlyCertifiedReference=false`. PR63 independently reviewed the checking-only primary-versus-companion comparator using synthetic legacy float64 bundles; it likewise did not certify a native reference.

Meanwhile, `tools/h1_native_batch.py:prepare` still calls `h1.reference.prepare(spec)` to regenerate **legacy checking centres**. Seven original static C/G/A fields fail source-exact physical 100× even though the inherited 64-ULP native comparison may pass. A hand-edited reference JSON is not a repair: the runner's re-preparation and saved file/seal comparison would detect drift, and self-consistent new seals do not authenticate an expected reference chosen *before* viewing results.

## Explicit proposed architecture

The machine-readable `migration-plan.json` pins the entire baseline source lineage with exact original model, study and source-facts SHA256, plus actual Git-blob identities of the current interval generator, comparator, existing checker, temporal policy, verifier, plan and native batch runner. `check_migration_plan.py` verifies those Git blob contents from the same on-disk bytes, the three original source SHA256 identities and the unchanged legacy runner's old preparation call. It refuses mutations, unknown fields and any proposed authority/status promotion. The receipt always returns `DESIGN_VERIFIED_NATIVE_BLOCKED`; it does not make an executable runner plan or permit a native command.

**Future, in a distinct separately reviewed implementation:** introduce an explicitly versioned **general H1 graph checking-reference adapter**, not a hidden apparatus-specific alternate solver. It must bind the exact original T1-T source and the two authorized analysis-only companion descriptors to an independently checked physical interval reference. It must handle all required exports and original local allowance and sealed temporal/integral budgets, and prepare/serialize each new N1-only reference deterministically; the entire physical 100× obligation must be independently accepted, not inferred from a self-check alone.

The actual runner must have a new explicit **version-dispatch and fail-closed read-only expected-seal binding**, with a prospective trust anchor independent of the generated bundle or caller-selected fingerprint. It must compare an externally committed expected bundle SHA and semantic seal against the re-prepared bytes **before execute**. No fallback to `h1.reference.prepare` for an unrecognized new version, no in-place mutation of historical bundles or broadening of source/physical tolerances. Reference bundle schema migration is a new reviewed trust/evidence behavior, not automatically enabled by this plan.

## Normative future authority and pre-output trust contract — F-01

This section specifies **future admission obligations**, not a presently authenticated external manifest or operating authorization. The machine contract is expectedManifestContract in migration-plan.json; its manifest schema is sim_heat.h1_n3.owner_approved_expected_manifest/1. The external approved manifest, trusted public key, protected approval event, authorized host and attempt ledger **do not exist yet**. An implementer MUST refuse the future N1 path until these can actually be verified.

**Who is allowed to approve:** The project owner, authenticated as the GitHub account physicsvigilante, must explicitly approve the precise native attempt and the exact expected references. A separate R2 review record must have approved the fixed checker/code closure and physical certificate for the exact scope before owner approval. Independent Chat B review is independent *context*, not independently authenticated human or cryptographic authority. An implementer, calculator or CI job preparing a reference cannot approve its own expected bytes. A contributor may propose a candidate approval record but cannot grant it.

**Where authority comes from:** The only planned authority source is a content-addressed manifest in physicsvigilante/review_sandbox at a protected, owner-approved Git commit under projects/sim_heat/native-approvals/<attemptId>/. The future runner release MUST pin an independently approved owner Ed25519 verification key (including key ID and key-source revision); the manifest must carry a detached signature over its exact RFC 8785/JCS UTF-8 canonical bytes. The approval envelope, separate from those signed bytes to avoid self-referential Git commit hashes, must contain the protected Git commit SHA, approved path, exact manifest blob SHA-256, owner identity, owner-signature SHA-256 and key ID, independent review report blob, GitHub approval event ID and **GitHub server timestamp**, runner release commit and attempt-claim ledger record ID. A mutable branch name, self-supplied public key, local file outside the attempt, unprotected Git commit, signed-but-unreviewed candidate, or semantic seal created by reference.prepare is **not an authority**. Branch protection, required approvals, signature checks and applicable permissions must be independently attested; if unavailable, REFUSE rather than assume protections.

**Precise object binding:** The signed expected manifest must contain the reviewed candidate HEAD **and full Git tree**, checking version, complete checking-source closure and dependency-lock SHA-256, original model/study/source-facts SHA-256, all three original/analysis-only descriptor identities and SHA-256s, exact expected exported names/units, accepted independently reviewed physical 100x full-grid certificate SHA, host identity (image, OS, architecture, OMC binary and runtime libraries, MSL source tree manifest, Python/dependency hashes and required resource/network containment), approved GitHub workflow/branch/ref, single-use attempt nonce and the original hard ceilings (one query, one build and one launch per three ordered cases, no retries). Each of three distinct primary/tight/dense expectations MUST contain case ID, study descriptor bytes SHA, bundle bytes SHA-256, semantic seal, grid SHA, source/certificate/code closure SHA, local scale and allowance SHA, quadrature SHA, temporal policy SHA, exported names/units SHA and checking version. No field may be inferred from a candidate's CSV, native MAT, a newly computed checker bundle or a caller-supplied expected hash.

**Chronology and attempt lease:** The authenticated GitHub server approval event and protected manifest-commit server record MUST be strictly earlier than the authorized GitHub Actions run creation and **any** native output for the attempt. The future runner must compare those trusted server-side event identities/timestamps, not a developer-supplied clock or mutable file mtime. Before the FIRST compiler version query, install, build or simulation, it must atomically claim the exact attempt ID in a separately protected, durable, append-only ledger using a compare-and-swap or equivalent single-use transaction; record the authenticated run ID/attempt, approved commit and manifest hash. It MUST refuse a second claim, a changed run ID, a missing authorization, late/re-approved evidence, already recorded output from the same attempt, fake GITHUB_* environment, or a non-first run_attempt. If protected approval metadata, trusted clock ordering or atomic ledger cannot be demonstrated, remain NATIVE BLOCKED.

**When loaded:** Load and authenticate the *external* expected approval envelope and manifest BEFORE any checker preparation or OMC operation, then verify/re-verify the same protected expected manifest and attempt lease before each of the three prospective invocations. Compare an actual **re-prepared** bundle to the independently committed expected byte SHA and semantic seal before any OMC action, including the first version query. Never promote a self-consistent bundle, caller-chosen seal, newly emitted attempt receipt, post-output recalculation or after-the-fact signature to the expected source. A changed expected artifact must require an entirely new approved attempt identity, and cannot silently replace a prior failed attempt or count as a retry.

## Normative future versioned bundle and runner interface — F-02

The following table is a **prospective, unimplemented compatibility contract**. The current native runner still calls legacy h1.reference.prepare(spec), and the existing verifier admits only legacy sim_heat.reference_bundle/2. No N3 version dispatch, N3 bundle serializer, trusted external approval or general H1 interval solver has been implemented.

| Scope | Checking-version selector | Bundle schema | N1 authority |
|---|---|---|---|
| Existing legacy H1 only | h1.reference.prepare/legacy | sim_heat.reference_bundle/2 | **Never valid for N1 migration**; seven old physical-100x centres still refuse |
| Future N1 versioned checker | sim_heat.h1_n3.physical_interval_reference_v1 | sim_heat.h1_n3.reference_bundle/1 | Prospectively admissible ONLY after explicit approved-manifest dispatch, independent certificate and full preflight |
| PR62 source-only mathematical candidate | sim_heat.h1_n1.interval_reference_candidate/1 | same candidate schema | Diagnostic data only; NEVER a runner-consumable reference |

The future runner MUST use an explicit exhaustive version table. Every N1 descriptor's checking version must match the independent *externally signed* manifest; the code closure, dependency lock, case ID, study SHA and schema must all agree. Unknown or missing version, version mismatch, mixed old/new schema, implicit default, legacy fallback, unrecognized output type and a version arriving in an unreviewed runtime release **REFUSE before any OMC**. The existing H1 legacy prepare and verifier are not modified by this DESIGN PR. A future new-schema adapter must be separately implemented/reviewed; the unchanged legacy verifier must reject the N3 bundle until such an adapter exists.

**Normative N3 bundle shape:** The future schema sim_heat.h1_n3.reference_bundle/1 requires exact fields for checkingVersion, referenceCaseId, sourceFactsSha256, originalModelSha256, studySha256, spec/specSha256, exact original grid, all mandatory columns and units, owners, network temperature envelopes, local scales and allowances, temporal policy, flow integrals and quadrature allowances, calculation method, implementation closure SHA, dependency lock SHA, independent physical certificate SHA, semanticSeal, and explicit nativeQualified=false/nativeExecuted=false. No missing, duplicated, unaudited or aliased output may be filled from the reference. The source-only PR62 JSON is not this bundle; compatibility cannot be asserted by renaming a schema string.

**Canonical byte/semantic identity:** Use RFC 8785 JCS canonical UTF-8 JSON for the future bundle and signed manifest, reject duplicate object keys, invalid types and any NaN, Infinity, exponent overflow or ambiguous/noncanonical numbers, and encode exact decimal source facts as separately specified canonical decimal strings rather than silently re-rounding inputs. The semantic seal is SHA-256 over a *domain-separated* canonical object with semanticSeal omitted (prefix identifies sim_heat.h1_n3.reference_bundle/1). The bundle byte digest is SHA-256 of the **complete canonical serialized bundle including its semanticSeal**. Both identities are externally approved before native output and independently compared against each freshly prepared bundle and its two isolated clean-replay copies; a self-generated semantic seal by itself is not trusted. Any discrepancy refuses with original evidence preserved. The future independently reviewed serialization policy must define canonical forms for every numeric and array field, and lock dependency versions and implementation bytes.

**Physical certificate / generality:** The independently reviewed Level-P physical target must derive from exact source decimal rational inputs and rigorous mathematical Pi, NOT merely binary64 operational similarity. The future certificate must bound each of **77 internal exports, eight public observations and five energy integrals at every required sample** (primary and tight each 2,401 samples, dense 4,801), within 1/100 of each unchanged native acceptance allowance. For static C/G/A the existing native comparison is 64 ULP and the physical reference error budget is **0.64 ULP**; no exceptions, per-network-scale substitution or fitted results. For dynamic K/W/J preserve the original own-output local scale, signed heat flow, independent integrals and strict per-channel temporal/quadrature budgets with no interpolation. Primary-only companion comparisons must retain BOTH separately passed original H1 per-run checks and use the frozen primary allowances. Before claiming the checker **general H1 graph** capable, an unfamiliar supported thermal composition selected after the checker interface freeze must pass source/provenance, mandatory exports, reference accuracy, sign/balance and public request checks **without editing the core checker/solver/runner**; the fixed T1-T case alone is inadequate.

**Normative refusal matrix:** The machine-readable futureRefusalMatrix in migration-plan.json specifies a mandatory REFUSE_BEFORE_ANY_OMC for missing/stale or unsigned approval, wrong signer/root, absent protected approval revision, evidence approved after the workflow/native output, reused attempt lease, crossed case IDs/seals, changed host/implementation dependencies, unknown version, old fallback, mixed schemas, altered primary allowance or grid, missing exact-physical 100x certificate, missing 77+8+5 coverage, incomplete two-run replay, post-output self-reseal and absent unfamiliar-case generality test. The runner must also recheck relevant immutable pins before each of the three future invocations and stop immediately on unexpected change without spending additional run slots. These refusals are **future requirements**; this design checker does not implement native preflight or authorize the runner.

## What this design expressly does NOT qualify

Neither reference self-check nor a static Git hash certifies scientific correctness of the general graph checker. A real host is not attested by Python package versions, an Ubuntu label or a text file declaring compiler identity. The original lost pre-author hidden key cannot be reconstructed by later successful experiments. The old seven static physical-100× failures and eight native blockers remain **evidence**, not warnings to suppress. The design avoids new apparatus-specific runner branches, but actual generality, LLM authorability and teacher-facing visualization must be demonstrated in later tests.

**No native actions, no merges, no copying synthetic comparator fixtures into a real reference bundle and no historical C1 changes.** After this bounded design is tested and independently reviewed, implement the future versioned checker and explicit migration wiring in a NEW milestone, not by changing the reviewed PR63 code.
