# H1-N4 — generic exact-source static physical candidate (OFFLINE ONLY)

This N4 milestone introduces **graph-independent, reusable arithmetic** for supported H1 thermal components. A new supported combination of `Body`, `RodArea` and `RodCircular` facts is evaluated without adding another apparatus-specific solver, rule, or quantity mapping. It does not import production Modelica, trust an LLM's solved answer, or read a native simulation.

For each body: `C = m c`. For each rectangular/area rod: `G = k A/L`. For each circular rod: `A = πd²/4` and `G = k A/L`, where π is rigorously enclosed by an exact-rational Machin alternating series. Source decimal strings are parsed exactly using `Decimal` and `Fraction`; correctly rounded nearest-even binary64 centres are selected with integer arithmetic only when both exact physical enclosure endpoints round to the **same binary64 bits**. Every output must satisfy the original 64-ULP native static allowance and the stricter **0.64-ULP / 100× reference accuracy** condition against mathematical **source-exact physics**, not the legacy float operation order. Refuse when the proof is ambiguous or the budget fails, rather than widening tolerance or fitting against candidate output.

This is one reusable static building block, **not a full graph solver**. It does not certify heat-flow time histories, spatial phenomena, all 77 exports, eight public observations, five integrals, source interpretation fidelity, real compiler semantics, or a future runner bundle. The input is independently expressed `sim_heat.reference/1` physical facts supplied as raw UTF-8 bytes with a matching SHA-256. The caller-supplied hash is an integrity assertion, **not** an external owner approval. Facts are parsed from precisely the bytes hashed; type/field/identifier/node, explicit geometry, bounded decimal and graph-incidence checks fail closed. No unspecified geometry is manufactured.
