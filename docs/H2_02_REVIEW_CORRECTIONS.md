## Narrow correction

**F-01 — confirmed blocker:** An invalid case digest stopped central plotting but left previous case model, historical run link, boundary power, body energies, graph counts, time, units, legend and explanatory statuses visible. `viewer/network/app.mjs` now invalidates and clears all case-bound source identity/quantitative UI and graphic nodes **at the start** of case selection, not only after failure. On a refusal, no prior data remain displayed as if they belong to the selected case. Unaffected source catalog remains available for another selection.

**F-02 — confirmed blocker:** A pending full CSV import could continue after a different case selection and apply old D1 rows under a new D2 provenance. The application now has monotonically advancing case/import epochs. Every import captures the immutable selected case and its epoch before any awaits; it checks ownership after `File.arrayBuffer()`, after cryptographic+numeric parsing, and before every UI success/error mutation. Case switches invalidate all outstanding imports (including previously pending error statuses) and suppress outdated case fetch responses.

**F-03 — confirmed major:** The former schema accepted physically wrong port_a/port_b direction or swapped owner temperature/energy/power channels as long as column suffixes existed. The strict, unchanged-format `validateCase` now requires exact `node.id.T`, `node.id.dU`, `node.id.Q_to_network` ownership, one and only one legitimate body/boundary owner port per named node, no body port on an ownerless junction, no duplicated port across ideal nodes, complete real rod endpoints, and edge `from`/`to` equal to the owners of that rod's `port_a`/`port_b`. A junction's named temperature channel must be from a rod endpoint **in that same node**. Valid native cases (D1, D2, DEV_BRIDGE) remain byte-identical; the contract still requires a trusted source adapter that maps actual compiled models and native outputs. Hash integrity alone does not establish measurement authentication.

**F-04 — confirmed minor:** A saved flow sequence +/0/+ or −/0/− merely touches zero and must not be reported as reversal. `firstSignChange` now requires two recorded samples of *opposite nonzero signs*. Zeros between them are ignored for the sign test; it reports the recorded bracketing times, **not** an invented exact crossing. Existing physical bridge −/+ bracket remains 1720–1730 s.
