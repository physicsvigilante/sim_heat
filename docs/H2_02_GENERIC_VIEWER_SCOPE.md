# H2-02 — General thermal network explorer, read-only data contract

**2026-11-15 | R2 for reusable topology, signed-observation and native provenance presentation.** This scope is a completed-feature candidate, not permission to merge or a claim of physics qualification. Source starting baseline: the owner-merged H2-01 `main` at `a33a0d79da405ff4c7191b9bfb94e096b10e2a9f`.

## Desired behavioral contract

**One generic renderer** displays any network admitted under the existing small H1 component grammar—finite heat-capacity bodies, fixed-temperature boundaries, storage-free rods (area or circular cross-section), and legal storage-free junctions—**provided** a trusted complete native run and a correctly generated case bundle exist. Adding a new network is data authoring; the renderer and solver do not acquire case dispatch. No geometry is inferred: diagram positions, line lengths and loops are topological illustration only.

The offline adapter `viewer/network/tools/build_case.py` uses the unchanged `h1.study.load_study` / `h1.model.topology` / `h1.decoder.decode_csv` to derive owner bodies/boundaries/junctions, port-accurate oriented rod edges and the exact available native observation channels. The builder does **not** invoke OMC or solve trajectories or make reference-based missing-result repairs; it refuses on a wrong ZIP hash, failed native attempt, mismatched model/study byte identities, missing native required output, stale MAT/CSV digest, wrong time grid or native qualification mismatch. Unlike a proposed physics compiler service, this operates only with already trusted and approved archived runs and files. It is not a hostile-input sandbox.

The output uses strict `sim_heat.viewer.native_case/1` plus source-catalog `sim_heat.viewer.case_index/1`. Each bundle records exact historical ZIP, model, study, MAT and CSV SHA-256, Git executed commit, native run/artifact ID, source folder, check count, `diagnostic_only`, `nativeQualified=false`, analysis grid, each source node and port group, each rod's native orientation and observed field, and a bounded selection of **actual saved time samples**. Every quantity has a fixed native-origin unit (temperatures K, signed rod/boundary powers W, cumulative stored-energy changes J). Body energies may be summed with body energies in J; no mixing with instantaneous W or new energy-conservation verdict is permitted.

For all original canonical samples, the browser can verify the user's **exact native normalized CSV** against the recorded source SHA-256 and grid. An incorrect/unavailable file refuses, without interpolation, guessed values, or remote upload. The repository catalog itself is *tracked source data*, not an independently cryptographically anchored authority: per-file SHA is an anti-accidental-drift integrity check relative to that catalog, not independent execution authentication. Native histories remain unqualified diagnostics; a viewer acceptance is not H1 scientific qualification.

## Demonstrations and exclusions

Required cases (all recorded native runs): D1 one body + one boundary + one rod; D2 two bodies + one rod; DEV_BRIDGE two boundaries + two bodies + five rods. These have different node types, energy/boundary-power availability, analysis intervals and edge counts. Their original numerical histories are independently copied as a **lossless selection** from the native output, not an analytic or refitted solution. Cases can be switched without modifying renderer JavaScript; a fourth supported native arrangement requires only new case data and one source catalog entry.

Tests must cover the three historic CSV/graph comparisons, data-only UI switching, visible signed rod arrows and negative boundary power interpretation, a bridge-only sign reversal that is not falsely claimed for D1/D2, K/J/W separation, ownerless junction representation, unknown native export and malformed topology refusals, false native qualification refusal, missing/stale preview and full CSV SHA, non-identical terminal duplicates, and actual desktop/mobile Chromium interaction. The normal 151 H1 tests and four arithmetic tests must also run on final-head CI. No new OMC build/launch and no engine edits. Original first failed attempts and historical artifacts remain linked and immutable.

**Outside this milestone:** model editing, new physical laws, numerical algorithms, browser-triggered simulation, symbolic/inverse solving, actual apparatus shape/pose, new qualification semantics, independently certified reference tolerances, unfamiliar-author C1 transfer, complete problem set, and real classroom trials. A future H2-03 teacher-controlled simulation is a distinct higher-risk milestone.

## Shared review and release gate

Develop and self-test in a source branch, publish a **draft PR with passing CI on its exact head SHA**, then create a focused **R2** review packet in `physicsvigilante/review_sandbox/projects/sim_heat/pr-<PR>/` under the central protocol. The user gets a short ready-to-paste second-ChatGPT prompt. Chat B independently reviews pinned source, native evidence hashes, graphs, units, refusal controls and screenshots, and writes its own new report to that central repo. On “Review complete,” retrieve and address findings, rerun CI after code changes and request only targeted re-review unless semantics expand. **No merge without separate owner approval**, and any approved merge requires verified post-merge CI and a central record update.
